# Relay — 跨仓库提交迁移设计说明

> 本文与 `designs/commit-relay/index.html` 当前交互原型同步。产品以 Windows 桌面应用为目标，原型优先保证 900 × 600 及以上窗口可用。

## 1. 产品目标

Relay 帮助开发者在 Git / SVN 仓库之间迁移选定提交。它需要让用户在执行前明确知道：从哪里迁、迁哪些提交、写到哪里、文件路径如何对应、哪些改动可自动处理，以及仍有哪些风险需要确认。

## 2. 当前主流程

| 步骤 | 名称     | 主要任务                       | 继续条件                         |
| ---- | -------- | ------------------------------ | -------------------------------- |
| 1    | 源仓库   | 选择提交来源仓库               | 已选择仓库                       |
| 2    | 选择提交 | 搜索、加载并多选提交           | 至少选择 1 条提交                |
| 3    | 变更预览 | 按文件检查增、删、改内容       | 可直接继续，也可返回修改选择     |
| 4    | 目标仓库 | 选择迁入仓库，配置路径对应关系 | 目标与源不同，路径规则有效       |
| 5    | 迁移     | 核对执行摘要，处理风险并执行   | 所有“需确认”和“需人工处理”项完成 |

侧栏固定展示五步状态。已完成步骤可返回，未到达步骤不可点击。设置独立于迁移步骤，返回迁移后保留原进度。

## 3. 页面要求

### 3.1 源仓库

- 以卡片展示仓库名称、本地路径、Git / SVN 类型、分支或 SVN 路径、最近使用时间。
- 支持添加仓库；名称和本地路径为空时不能保存。
- 仓库弹窗打开后焦点进入弹窗；按 `Esc` 关闭；键盘焦点不会跑出弹窗。

### 3.2 选择提交

- 提交行展示短编号、说明、作者、日期和变更文件数。
- 支持按编号、说明、作者和日期搜索。
- 支持全选当前搜索结果、取消全选和分批加载。
- 提交行必须可用键盘选中，并向辅助工具说明当前是否已选择。

### 3.3 变更预览

- 顶部汇总新增、修改、删除文件数量，以及总增加和删除行数。
- 左侧显示文件列表，右侧显示当前文件差异。
- 文件行可用键盘选择，并向辅助工具说明当前文件。
- 在较小窗口中可收起文件列表，让差异区域获得完整宽度。

### 3.4 目标仓库与路径对应

- 目标仓库不能与源仓库相同。
- 默认保持原目录结构并写入目标仓库根目录。
- 开启自定义对应关系后，可添加、删除和上下调整规则。
- 每条规则包含源路径前缀和目标路径前缀；空值或重复源路径会阻止继续。
- 页面实时显示有效规则预览，并说明规则按从上到下的顺序匹配。

### 3.5 迁移与风险处理

页面先展示紧凑执行摘要，包括迁移路线、提交数、文件数、迁移模式和提交方式。默认高度控制在一行内，用户可展开查看完整信息：

- 源仓库和目标仓库；
- 提交数和文件数；
- 迁移模式；
- 保留原提交或合并为单次提交；
- 目标路径和路径对应规则；
- 合并提交时使用的提交说明。

为保证代码阅读空间：

- 提供“专注预览”，进入后收起页面标题、执行摘要和迁移设置，只保留文件状态、代码工具和底部执行入口；按 `Esc` 或点击按钮退出。
- 差异区提供 90%–120% 的代码字号调节，只改变代码，不缩放按钮和其他界面文字。
- 900 × 600 等较矮窗口继续默认使用紧凑摘要；展开详情是用户主动操作。

文件按以下状态分组：

| 状态       | 含义                 | 用户操作                                   |
| ---------- | -------------------- | ------------------------------------------ |
| 可自动应用 | 当前结果可直接写入   | 无需处理，可查看差异                       |
| 需确认     | 会覆盖或完整写入文件 | 接受写入；之后可以撤销                     |
| 需人工处理 | 检测到重叠冲突       | 在外部编辑器修改后重新检测；通过后可以撤销 |

不能仅凭用户点击“已解决”放行冲突。用户必须触发重新检测，检测通过后才算完成。改变迁移模式、提交方式或路径规则后，已有确认和检测结果全部失效，需要重新核对。

### 3.6 执行确认与进度

- 点击“核对并执行”后打开最终确认弹窗，重复显示路线、目标位置、提交数、模式和路径规则。
- 弹窗明确提醒迁移会写入本地目标仓库；用户可以返回检查或确认执行。
- 执行时显示阶段、当前处理对象和进度，不使用只有转圈图标的等待状态。
- 阶段至少包含：准备目标仓库、读取提交、生成迁移计划、写入文件、创建提交。
- 完成页展示来源、目标、提交数、文件数和耗时，并提供查看详情、返回首页和打开目标仓库。

## 4. 设置与历史

- 仓库设置支持搜索、添加、编辑和移除。
- 编辑器设置支持选择默认编辑器和添加自定义编辑器。
- 迁移记录展示时间、来源、目标、提交数、文件数和结果，并可查看明细。
- “关于和更新”展示当前版本、上次成功检查时间和手动检查入口。
- 后台发现新版本后，在 Windows 标题栏控制按钮左侧展示紧凑提示；点击直接进入更新页。
- 新版本卡片展示版本、发布时间和更新说明，并区分“稍后处理”与“下载并安装”。
- 下载中必须同时展示百分比和进度条，并提示完成后应用会自动重启。
- 检查失败时说明当前版本仍可继续使用，不能让失败提示看起来像阻断错误。
- 原型提供“原型状态”切换，仅用于评审尚未检查、已是最新、发现新版、下载中和失败状态，不属于正式产品控件。

## 5. Windows 与窗口适配

- 主要窗口按 Windows 桌面信息密度设计，不依赖 macOS 字体或窗口控件尺寸。
- 900 × 600 是最低可用尺寸；主步骤、底栏和关键操作不能被裁掉。
- 窗口较窄时，路径规则改为纵向排列；预览和迁移页提供文件列表收起入口。
- 窗口较矮时减少非关键留白，内容区独立滚动，固定底栏仍可操作。
- 迁移页紧凑摘要下应保留可阅读的差异高度；专注预览下代码区成为页面主体。
- 所有可点击行使用真正的按钮语义；明显的键盘焦点不能被移除。
- 次要文字仍需在深色背景上清晰可读，不能只靠极低透明度表现层级。

## 6. 完成标准

- 五步顺序与当前产品一致：源仓库 → 选择提交 → 变更预览 → 目标仓库 → 迁移。
- 目标页可以完整管理并校验路径对应规则。
- 迁移页能区分自动、确认和人工处理三种结果。
- 确认与人工处理均可撤销；冲突必须重新检测后才能放行。
- 执行前有最终摘要和确认，执行中有可理解的阶段进度。
- 执行摘要可展开和收起；专注预览可进入、退出，并支持 `Esc` 退出。
- 差异代码字号可在 90%–120% 之间调整，页面其他控件大小不变。
- 从选择源仓库到迁移完成的主流程可点击走通。
- 900 × 600 与常见宽屏尺寸下都没有阻断操作的裁切或横向溢出。
- 弹窗支持键盘进入、循环聚焦和 `Esc` 关闭；关键列表可用键盘操作。
- “关于和更新”页及标题栏新版本提示可点击走通，五种更新状态都能在原型中检查。
