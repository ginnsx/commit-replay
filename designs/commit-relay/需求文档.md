# Relay — 跨仓库提交迁移 产品需求文档

> 基于设计稿 `designs/commit-relay/` 整理，版本对应设计稿当前状态。

## 1. 产品概述

### 1.1 产品名称

**Relay** — 跨仓库提交迁移

### 1.2 产品定位

Windows 桌面应用，帮助开发者在 **Git / SVN** 仓库之间，将选定提交及其文件变更迁移到目标仓库。支持变更预览、冲突检测与手工解决，并通过外部编辑器打开冲突文件进行编辑。

### 1.3 目标用户

- 需要在不同代码库之间同步提交/补丁的开发者
- 维护 Git 与 SVN 混合环境的团队
- 需要跨分支、跨仓库 cherry-pick 或批量应用变更的场景

### 1.4 核心价值

| 能力 | 说明 |
|------|------|
| 多 VCS 支持 | 源/目标均可为 Git 或 SVN |
| 提交级选择 | 按提交粒度选择要迁移的变更 |
| 文件级预览 | 以文件为单位查看增/删/改及行级 diff |
| 冲突工作台 | 迁移前自动检测冲突，并排对比 + 外部编辑器解决 |
| 仓库与编辑器管理 | 持久化保存常用仓库与默认外部编辑器 |
| 迁移记录 | 保留历史迁移，可查看提交与文件变更明细 |

## 2. 信息架构

### 2.1 主导航（五步迁移流程）

侧栏「迁移流程」固定展示五个步骤，支持在已完成步骤间跳转：

| 序号 | 步骤 ID | 名称 | 说明 |
|------|---------|------|------|
| 1 | `source` | 源仓库 | 选择提交来源仓库 |
| 2 | `commits` | 选择提交 | 多选要迁移的提交 |
| 3 | `preview` | 变更预览 | 文件列表 + 行级 diff |
| 4 | `target` | 目标仓库 | 选择迁移目标（不可与源相同） |
| 5 | `migrate` | 迁移 | 冲突检测 / 冲突解决 / 执行迁移 |

**步骤状态：**

- 当前步骤：高亮
- 已完成步骤：显示勾选，可点击回跳
- 未到达步骤：禁用，不可点击

### 2.2 设置入口

侧栏底部「设置」独立于五步流程，包含三个标签页：

- **仓库**：仓库列表的增删改查
- **编辑器**：默认外部编辑器配置
- **迁移记录**：历史迁移列表与明细查看

设置页通过底部「返回迁移」回到迁移流程，不丢失当前步骤状态。切换标签页时，若处于迁移记录明细页则返回列表。

### 2.3 全局布局

```
┌─────────────────────────────────────────────┐
│ 标题栏：Relay — 跨仓库提交迁移  [─ □ ×]      │
├──────────┬──────────────────────────────────┤
│ 迁移流程  │  主内容区（步骤页面 / 设置）       │
│ 1~5 步骤  │                                  │
│          │                                  │
│ [设置]   ├──────────────────────────────────┤
│          │  底栏：状态提示 | [上一步] [下一步] │
└──────────┴──────────────────────────────────┘
```

- 主内容区在「变更预览」「冲突工作台」等场景下，内部区域独立滚动，底栏固定不被挤压。
- 迁移完成后隐藏底栏，展示成功页。

## 3. 功能需求

### 3.1 仓库管理

#### 3.1.1 仓库数据模型

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 唯一标识 |
| `name` | string | 是 | 显示名称 |
| `path` | string | 是 | 本地工作副本路径 |
| `type` | `git` \| `svn` | 是 | 版本控制类型 |
| `branch` | string | 是 | Git 分支名；SVN 路径（如 trunk、branches/release-2.4） |
| `lastUsed` | string | 否 | 最近使用时间（展示用） |
| `svnUser` | string | SVN 时 | SVN 用户名 |
| `svnPass` | string | SVN 时 | SVN 密码（加密本地存储） |

#### 3.1.2 添加 / 编辑仓库（弹窗）

- 字段：显示名称、本地路径（含浏览按钮）、版本控制类型、分支/路径
- SVN 额外字段：用户名、密码；提示「凭据将加密保存在本地」
- Git 分支默认 `main`；SVN 路径默认 `trunk`
- 保存后写入仓库列表；编辑时回填已有数据

#### 3.1.3 仓库管理页（设置 → 仓库）

- 搜索：按名称、路径过滤
- 表格列：名称、路径、类型（Git/SVN 徽章）、分支/路径、最近使用、操作
- 操作：编辑、移除
- 移除时：若该仓库正作为源或目标选中，应同步清除对应选择

#### 3.1.4 仓库卡片（源/目标选择页）

- 展示：名称、路径、VCS 类型徽章、分支/路径、最近使用时间
- 单选：点击选中，再次点击其他卡片切换
- 源仓库页头部提供「添加仓库」快捷入口

### 3.2 步骤一：选择源仓库

**页面标题：** 选择源仓库  
**副标题：** 从已保存的仓库中选择提交来源，或添加新仓库

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| SRC-01 | 展示所有已保存仓库卡片 | 网格布局，含 VCS 徽章与元信息 |
| SRC-02 | 单选源仓库 | 选中态视觉区分；底栏提示未选时「请选择一个源仓库」 |
| SRC-03 | 「下一步」门禁 | 未选源仓库时禁用 |
| SRC-04 | 快捷添加仓库 | 头部按钮打开添加仓库弹窗 |

---

### 3.3 步骤二：选择提交

**页面标题：** 选择提交  
**副标题：** 来自 {源仓库名} · 最近 N 条提交，已选 M 条

#### 3.3.1 提交选择器（`CommitPicker`）

列表区域为卡片容器，顶部工具栏 + 提交列表 + 底栏：

| 区域 | 内容 |
|------|------|
| 工具栏 | 搜索框（左）+ 全选/取消全选（右） |
| 列表 | 提交行，支持多选 |
| 底栏 | 已显示数量统计；有更多时显示「加载更多」 |

#### 3.3.2 文本搜索

- 搜索框占位：「搜索 hash、说明、作者…」
- 实时过滤，匹配字段：`hash`、`msg`（提交说明）、`author`、`date`
- 有输入时显示清除按钮（×）
- 无匹配结果：空状态「没有匹配的提交」+「清除搜索」
- 搜索条件变更时，分页重置为首批

#### 3.3.3 分页加载（加载更多）

采用 **「加载更多」按钮**，不使用滚动触底自动加载。

| 项 | 说明 |
|----|------|
| 每页条数 | `COMMIT_PAGE_SIZE = 8`（可配置常量） |
| 首次展示 | 当前筛选结果的前 8 条 |
| 底栏统计 | 「已显示 X / Y 条」；搜索时附加「（共 Z 条）」 |
| 加载更多 | 有更多数据时显示「加载更多（N 条）」；点击后追加下一批 |
| 加载态 | 按钮文案变为「加载中…」，期间禁用 |
| 加载完毕 | 无更多数据时隐藏按钮 |

**选型理由（设计决策）：**

- 桌面端操作更明确，用户主动触发加载
- 与搜索、全选语义一致：全选作用于**当前筛选结果的全部提交**（含尚未加载项）
- 避免列表内嵌套滚动与无限滚动误触

#### 3.3.4 多选与全选

- 点击行切换选中；选中行显示勾选
- 工具栏「全选」：选中当前筛选结果的**全部**提交（不限于已加载页）
- 若当前筛选结果已全部选中，按钮文案为「取消全选」
- 筛选结果为空时，全选按钮禁用

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| CMT-01 | 展示源仓库提交列表 | 每条含：hash、消息、作者、日期、涉及文件数 |
| CMT-02 | 多选提交 | 点击行切换选中；选中行显示勾选 |
| CMT-03 | 全选 / 取消全选 | 作用于当前筛选结果全部项；文案随状态切换 |
| CMT-04 | 「下一步」门禁 | 至少选 1 条提交；底栏显示「已选择 N 条提交」 |
| CMT-05 | 提交数据来源 | 从源仓库 VCS 分页拉取（设计稿为 mock 数据） |
| CMT-06 | 文本搜索 | 支持 hash、说明、作者、日期过滤；可清除 |
| CMT-07 | 分页加载 | 首批 8 条 + 加载更多；搜索变更时重置分页 |
| CMT-08 | 已选状态保持 | 翻页加载不影响已选提交；未加载项可被全选选中 |

**提交数据模型：**

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 |
| `hash` | 短 hash |
| `msg` | 提交说明 |
| `author` | 作者 |
| `date` | 提交时间 |
| `files` | 变更文件数 |

### 3.4 步骤三：变更预览

**页面标题：** 变更预览  
**副标题：** N 条提交 · 以文件为单位查看增删改

#### 3.4.1 汇总栏

- 统计：新增 / 修改 / 删除 文件数量（带颜色徽章）
- 行数统计：总 `+additions` / `−deletions`

#### 3.4.2 左右分栏

| 区域 | 功能 |
|------|------|
| 左侧文件树 | 文件列表，每项含状态徽章（新增/修改/删除）与完整路径；点击选中 |
| 右侧 diff 面板 | 展示选中文件的行级变更 |

#### 3.4.3 Diff 展示规则

- 行类型：`ctx`（上下文）、`add`（新增，绿色）、`del`（删除，红色）
- 每行显示：旧行号、新行号、变更前缀（`+`/`-`/空格）、代码内容
- 未选文件时右侧显示空状态：「选择左侧文件查看变更详情」

**文件变更数据模型：**

| 字段 | 说明 |
|------|------|
| `path` | 文件路径 |
| `status` | `add` \| `mod` \| `del` |
| `additions` / `deletions` | 行数统计 |
| `diff` | 行级 diff 数组 |

| 需求 ID | 描述 |
|---------|------|
| PRV-01 | 底栏提示「N 个文件待迁移」 |
| PRV-02 | 布局：面板内滚动，不挤压底栏 |

---

### 3.5 步骤四：选择目标仓库

**页面标题：** 选择目标仓库  
**副标题：** 提交将迁移至此仓库，迁移前会自动检测冲突

#### 3.5.1 迁移流向示意

- 左侧节点：源仓库（名称、路径、VCS 徽章）
- 箭头连接
- 右侧节点：目标仓库（未选时虚线边框 + 占位文案）

#### 3.5.2 目标选择

- 候选列表：排除源仓库后的所有已保存仓库
- 单选卡片，交互同源仓库页

| 需求 ID | 描述 | 验收标准 |
|---------|------|----------|
| TGT-01 | 目标不可与源相同 | 列表已排除；若逻辑上相同则底栏提示并禁用下一步 |
| TGT-02 | 「下一步」门禁 | 必须选择目标仓库 |
| TGT-03 | 未选时底栏提示 | 「请选择目标仓库」 |

---

### 3.6 步骤五：迁移确认与执行

**页面标题：** 确认迁移  
**副标题：** 检测目标仓库是否存在冲突，确认后执行迁移

#### 3.6.1 无冲突场景

展示迁移摘要卡片：

- 源仓库（名称 + VCS 徽章）
- 目标仓库（名称 + VCS 徽章）
- 提交数量
- 文件变更统计（新增/修改/删除数量）
- 状态行：「未检测到冲突，可以安全迁移」（绿色勾选）

底栏主按钮：**执行迁移**（可用）

#### 3.6.2 有冲突场景

顶部冲突横幅：

- 标题：「发现 N 处冲突」
- 说明：点击左侧冲突文件查看差异；需手工修改时用外部编辑器打开，逐文件标记已解决

进入 **冲突工作台**（见 3.7）。

底栏：

- 状态：「还有 N 处冲突待解决」
- **执行迁移** 按钮：存在未解决冲突时 **禁用**

#### 3.6.3 冲突全部解决后

- 冲突工作台消失，展示与无冲突相同的摘要卡片
- 状态行：「所有冲突已解决，可以执行迁移」
- **执行迁移** 按钮可用

#### 3.6.4 迁移完成

- 成功页：勾选图标 + 「迁移完成」
- 摘要：已将 N 条提交从 {源} 成功应用到 {目标}，共变更 M 个文件
- 按钮：
  - **查看本次记录** — 跳转至设置 → 迁移记录，并打开刚完成的记录明细
  - **开始新的迁移** — 重置流程至步骤一（清空源/目标/提交选择及冲突解决状态）

#### 3.6.5 迁移记录写入

执行迁移成功时，自动将本次迁移快照写入迁移记录列表（新记录置顶）：

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 |
| `completedAt` | 完成时间 |
| `source` / `target` | 源/目标仓库快照（name、path、type、branch） |
| `commits` | 本次迁移的提交列表快照 |
| `files` | 本次迁移的文件变更快照（含 diff） |
| `conflictsResolved` | 解决的冲突数量 |
| `status` | `success`（设计稿仅展示成功记录） |

| 需求 ID | 描述 |
|---------|------|
| MIG-01 | 进入迁移步骤时自动执行冲突检测 |
| MIG-02 | 有未解决冲突时禁止执行迁移 |
| MIG-03 | 迁移成功后写入迁移记录 |
| MIG-04 | 「开始新的迁移」重置源/目标/提交及冲突状态 |

### 3.7 冲突工作台

#### 3.7.1 布局

左右分栏：

| 左侧（冲突列表） | 右侧（对比视图） |
|------------------|------------------|
| 冲突文件列表 | 选中文件的并排 diff |
| 待解决计数 | 工具栏操作按钮 |

#### 3.7.2 冲突列表项

每项展示：

- 解决状态：已解决显示勾选图标
- 文件状态徽章（新增/修改/删除）
- 路径：**文件名在上、目录在下**（长路径 ellipsis，`title` 悬停显示完整路径）
- 冲突原因（单行 ellipsis，`title` 悬停完整内容）
- 列表项 **不含** 编辑器按钮

交互：

- 点击选中，右侧加载对应该文件的对比
- 已解决项视觉弱化（`resolved` 样式）
- 底部文案：「还剩 N 处待解决」

#### 3.7.3 冲突对比视图

**工具栏：**

- 左：当前文件完整路径
- 右：操作组（圆角容器内并排）

**操作组包含两个同等重要的按钮：**

| 按钮 | 样式 | 行为 |
|------|------|------|
| 用 {编辑器名} 打开 | 分裂按钮（青色） | 见 3.8.2 |
| 标记已解决 | 绿色，带勾选图标 | 将当前冲突标记为已解决；自动选中下一个未解决项 |

已解决的冲突文件：隐藏「标记已解决」按钮。

**对比区：**

- 表头：「目标仓库（当前）」| 「迁入变更（期望）」
- 并排行级对比，差异行高亮：
  - `add`：右侧新增
  - `del`：左侧删除
  - `chg`：两侧均有但内容不同
- 底部提示区：
  - 有重叠行时：「高亮行 X–Y 为重叠冲突区域…」
  - 显示将使用的编辑器名称
  - 显示目标仓库中的完整文件路径

**冲突数据模型：**

| 字段 | 说明 |
|------|------|
| `path` | 冲突文件路径 |
| `status` | 文件变更类型 |
| `reason` | 冲突原因描述 |
| `overlapLines` | `[start, end]` 重叠行范围 |
| `before` | 目标仓库当前内容（行数组） |
| `after` | 迁入期望内容（行数组） |

| 需求 ID | 描述 |
|---------|------|
| CFL-01 | 标记已解决后自动聚焦下一未解决冲突 |
| CFL-02 | 冲突解决状态仅前端确认（用户在外部编辑器修改后手动标记） |
| CFL-03 | 对比视图未选冲突时显示空状态 |

### 3.8 外部编辑器

#### 3.8.1 编辑器配置（设置 → 编辑器）

- 单选列表：预设 + 用户自定义编辑器
- 每项展示：名称、可执行文件路径（纯文字，无图标）
- 自定义编辑器可移除；预设不可移除
- 「添加编辑器应用」打开添加弹窗

**预设编辑器（设计稿）：**

VS Code、Visual Studio、Cursor、File Explorer、Terminal、Git Bash、IntelliJ IDEA、PyCharm

**编辑器数据模型：**

| 字段 | 说明 |
|------|------|
| `id` | 唯一标识 |
| `name` | 显示名称 |
| `exe` | 可执行文件路径 |
| `kind` | 类型标识（实现用） |
| `custom` | 是否用户自定义 |

#### 3.8.2 冲突页编辑器分裂按钮

位于对比视图工具栏，**仅此处**提供编辑器操作（不在冲突列表项中）。

```
┌──────────────────────┬───┐
│ 用 VS Code 打开       │ ▾ │
└──────────────────────┴───┘
```

| 区域 | 点击行为 |
|------|----------|
| 左侧主按钮 | 使用当前选中的编辑器，打开目标仓库中该冲突文件的本地路径 |
| 右侧箭头 | 展开下拉菜单，选择/切换编辑器（**不打开文件**） |

下拉菜单：

- 列出所有已配置编辑器（纯文字）
- 当前选中项高亮
- 底部「选择其他应用…」→ 打开添加编辑器弹窗
- 展开时箭头旋转 180°
- 点击外部关闭

打开文件后：Toast 提示「已用 {编辑器名} 打开 {完整路径}」

#### 3.8.3 添加编辑器弹窗

- 显示名称（必填）
- 应用程序路径（必填，含浏览按钮）
- 取消 / 添加

### 3.9 迁移记录

#### 3.9.1 记录列表（设置 → 迁移记录）

| 元素 | 说明 |
|------|------|

  - 目标仓库路径、分支/路径
  - 提交数量
  - 文件变更统计（新增/修改/删除数量及行数）

## 4. UI / 视觉规范（设计稿约束）

### 4.1 平台与窗口

- Windows 桌面应用风格
- 自定义标题栏：应用 Logo「R」、标题「Relay — 跨仓库提交迁移」、最小化/最大化/关闭
- 深色主题

### 4.2 色彩语义

| 令牌 | 用途 |
|------|------|
| `--accent` (#4ecdc4) | 主强调色、编辑器操作按钮 |
| `--add` (#3fb950) | 新增、已解决、标记已解决按钮 |
| `--mod` (#d29922) | 修改 |
| `--del` (#f85149) | 删除、危险操作 |
| `--git` / `--svn` | VCS 类型徽章 |
| `--warn` | 冲突警告横幅 |

### 4.3 组件规范

- **VCS 徽章**：Git（橙）/ SVN（蓝），含类型图标与文字
- **状态徽章**：新增 / 修改 / 删除
- **仓库卡片**：选中态边框高亮
- **冲突操作组**：深色圆角容器，内含分裂编辑器按钮 + 标记已解决按钮，两者视觉权重对等（青色 / 绿色渐变，同等高度 34px）
- **分裂按钮**：左侧文字区点击打开文件，右侧箭头点击展开编辑器选择；hover 分区反馈；展开时箭头旋转 180°
- **迁移记录列表项**：整行可点击，hover 高亮，右侧 chevron
- **迁移记录明细**：概览卡片 + 标签切换（提交 / 文件变更）
- **提交选择器**：卡片内工具栏（搜索框 + 全选）；底栏显示已加载数量与「加载更多」按钮

### 4.4 排版

- 界面字体：Segoe UI / 微软雅黑
- 代码/路径：等宽字体（Cascadia Code / Consolas）
- 冲突列表路径：文件名 13px，目录 11px 次要色

## 5. 业务规则汇总

| 规则 | 说明 |
|------|------|
| BR-01 | 源仓库与目标仓库不能相同 |
| BR-02 | 至少选择 1 条提交才能进入预览 |
| BR-03 | 存在未解决冲突时不能执行迁移 |
| BR-04 | 冲突「标记已解决」为用户手动确认，应用不自动检测工作副本是否已修改 |
| BR-05 | 移除正在使用的仓库时清除对应选择 |
| BR-06 | 删除当前默认编辑器时回退到第一个预设 |
| BR-07 | SVN 凭据本地加密存储 |
| BR-08 | 步骤导航仅允许跳转到当前步骤或已完成步骤 |
| BR-09 | 每次迁移成功自动追加一条记录，内容为完成时刻的快照 |
| BR-10 | 迁移记录按时间倒序展示，最新记录置顶 |
| BR-11 | 提交全选作用于当前搜索筛选结果的全部项，含未加载页 |
| BR-12 | 搜索或切换源仓库时，提交列表分页重置为首批 |

## 7. 设计稿范围外（实现时需补充）

以下能力在设计稿交互原型中 **未覆盖或为 mock**，开发时需单独定义：

1. **VCS 实际操作**：git log、svn log、diff 生成、patch 应用、冲突检测算法；提交列表服务端分页与搜索 API
2. **跨 VCS 迁移**：Git → SVN、SVN → Git 的变更映射策略
3. **路径映射规则**：源路径与目标路径结构不一致时的文件对应关系
4. **迁移执行细节**：是否生成新提交、提交信息模板、失败回滚
5. **冲突复检**：标记已解决后是否重新 diff 验证
6. **仓库浏览按钮**：文件夹选择对话框的实际实现
7. **编辑器启动参数**：各编辑器打开文件时的命令行参数差异
8. **网络/认证失败**、**仓库不可用** 等错误态 UI
9. **迁移记录管理**：删除、导出、存储上限与清理策略（设计稿未实现）
